# Telemetry privacy inventory

Allowed fields are timestamp, severity, environment, service, release, stable event/flow name, safe error code/type, bounded endpoint/job name, status/status category, duration, payload-size category, platform, app/build version, retry/queue aggregate counts, and a random correlation/run ID. Phase 7 emits no account identifier or actor hash. Introducing a pseudonymous actor identifier later requires a documented purpose, keyed one-way construction, bounded retention, privacy review, and new redaction tests; it must never be the raw account identifier.

Forbidden fields include authorization/cookies/JWTs, credentials/secrets/DSNs/keys, service-role material, raw or signed URLs, Storage bucket/object paths, Expo push tokens, notification/review/comment/chat bodies, room or restaurant names, email, precise IP/location, profile fields, screenshots, view hierarchy, request/response bodies, and raw provider payloads. Sentry user identity remains unset and is cleared during account teardown.

Sentry retention should be the shortest period that supports incident response, initially 30 days for errors and 14 days for performance traces, subject to the organization privacy policy and regional requirements. Database scheduler history is retained 30 days; operational cleanup runs daily. Access is least privilege, audited, and limited to engineering on-call/security roles. DSAR/deletion procedures must include any configured telemetry provider capabilities; because identity is deliberately absent, correlation uses release/time/random request identifiers rather than personal data.

Telemetry is collected only to diagnose crashes, regressions, dependency failure, queue health, scheduler execution, and recovery. Sampling is environment-specific and production traces are sampled; crashes and explicit operational failures are retained within the limits above. Default PII, IP collection, precise device/location data, screenshots, view hierarchy, and raw breadcrumbs are disabled. Sentry and the selected hosting/database providers are data processors whose region, subprocessors, access, deletion, and retention terms must be approved before deployment. Logout and account deletion clear any SDK user association even though Phase 7 does not set one.

Phase 8 must update the public privacy policy, Apple privacy manifest/store questionnaire, Google Play Data safety declaration, support/DSAR procedure, processor list, and retention disclosures before store submission. Development console logs remain local/test-only; production signals use the structured contract and configured telemetry project.

Before adding a signal, document purpose, fields, source, retention, access, and runbook. Tests must prove redaction and must not use real user data or production credentials.
